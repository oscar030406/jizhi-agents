# 部署说明

线上实例 https://jizhi.chenmingkun.cn 不登录即可访问公共课程墙与全部示例课，评审可直接使用。本文供需要本地复现或自行部署时使用。

## 一、系统构成

| 服务 | 技术栈 | 监听 | 职责 |
|---|---|---|---|
| classroom | Next.js 16 / React / TypeScript，Node ≥ 20.9，pnpm 10 | 3210（生产）/ 3000（开发） | 课堂产品层：造课编排、教学履约合同、讲义与互动教具渲染、发布门、学情报告、机构管理端 |
| agent-engine | Python 3.12 / FastAPI / LangGraph | 8001，仅本机 | 多智能体引擎：学情诊断、领域检索、生成、双判官审核、仲裁、反馈决策、导学 |
| PostgreSQL 16（可选） | | 5432 | 账号与服务端持久化；未配置时以访客模式运行 |

课程数据落在 `apps/classroom/data/`（含公共课程墙 `classrooms/` 与生成任务 `classroom-jobs/`），语料与索引落在 `apps/agent-engine/data/`。两处都要持久化。

## 二、本地启动

```powershell
# 1. 引擎
cd apps/agent-engine
pip install -r requirements.txt
copy .env.example .env          # 至少填 SILICONFLOW_API_KEY；AI_SERVICE_TOKEN 与课堂侧 GROUNDING_TOKEN 保持一致
python -m uvicorn app.main:app --port 8001

# 2. 课堂
cd apps/classroom
pnpm install
copy .env.example .env.local      # 填模型 key，GROUNDING_URL=http://127.0.0.1:8001，GROUNDING_TOKEN 同上
pnpm dev
```

或在仓库根执行 `scripts\start-demo.ps1`，脚本会加载引擎 `.env` 并拉起两个服务。打开 http://127.0.0.1:3210 即可造课。

知识库数据包（教材语料切片与索引）不随仓库发布，按书单登记向项目组索取，解压到 `apps/agent-engine/data/`。没有数据包也能运行，生成自动降级为通识模式，页面明确标注「未接地」，不伪装成有据。

### 配置项

| 变量 | 位置 | 说明 |
|---|---|---|
| `SILICONFLOW_API_KEY` | 引擎 `.env`、课堂 `.env.local` | 模型服务密钥。密钥即开关：缺 key 时生成环节显式报错，不静默退回规则。 |
| `LLM_PROVIDER_FAST / STRONG / JUDGE`、`LLM_MODEL_*` | 引擎 `.env` | 三档模型路由。路由禁用时对应环节显式失败。 |
| `AI_SERVICE_TOKEN` ↔ `GROUNDING_TOKEN` | 引擎 ↔ 课堂 | 课堂调引擎的内部鉴权，两边必须一致，只能用 ASCII。 |
| `GROUNDING_URL` | 课堂 `.env.local` | 引擎地址，本地为 `http://127.0.0.1:8001`。 |
| `AUDIT_MODEL`、`ARBITER_MODEL` | 课堂 `.env.local` | 双判官与仲裁模型。 |
| `GITHUB_TOKEN`（选填） | 引擎 `.env` | 实操项目侦察用 GitHub 公开 API 搜仓库。不配按匿名配额跑（搜索 10 次/分、拉 README 60 次/小时），一次起草约 18 次搜索加最多 14 次 README，同一 IP 一小时最多跑 4 次；配上只读 PAT（public_repo 权限即可）后配额升到 30 次/分、5000 次/小时，代码按请求头自动切节拍。演示前建议配上。 |

## 三、生产部署

生产采用不可变发布：每次发布是一个带 git sha 的独立目录，服务通过 `current` 链接指向它，回滚即改链接。流程三步，全部脚本化，不在服务器上手改文件。

1. **本机构建**。仓库根执行 `scripts\deploy\build-release.ps1`，产物在 `tmp\deploy\release-<sha>-<id>\`，内含课堂 standalone 包 `classroom-next-<sha>.tgz`、引擎包 `agent-engine-<sha>.tgz`、`manifest.json`、`SHA256SUMS`、`apply-release.sh` 与两份 systemd 加固配置。构建时剥离代理环境变量，`NEXT_PUBLIC_*` 在此刻内联。
2. **上传**。整目录 scp 到服务器 `/root/jizhi-release-staging/<release-id>/`，root 属主，文件 0644、脚本 0755。
3. **切换**。root 执行 `bash apply-release.sh <release-id> /root/jizhi-release-staging/<release-id>`。脚本依次：校验暂存目录的文件集合、属主、权限与 SHA256；校验 tar 成员无路径穿越；解包到 `/opt/jizhi-web/releases/<id>` 与 `/opt/jizhi-engine/releases/<id>`；用锁定的 `requirements.production.lock` 建引擎 venv；停两个 systemd 服务，切 `current`，装加固配置，重启；最后自检并打印一行 `release=<id> web=standalone engine=ok users=nonroot auth=verified`。任一步失败即中止，`current` 不动。

运行时事实（2026-09-02 线上）：

- `jizhi-web.service` 以非 root 用户运行 `node /opt/jizhi-web/current/start-standalone.mjs`，监听 127.0.0.1:3210；`jizhi-engine.service` 以非 root 用户运行 venv 内的 uvicorn，监听 127.0.0.1:8001。
- nginx 监听 80/443，443 反代到 3210。生成过程走 SSE，对应路由需关闭代理缓冲并放长读超时。
- 主机 2 vCPU / 3 GB 内存。不要在服务器上执行 `pnpm build`，实测会把整机压死；这也是采用本机构建、上传成品的原因。
- 切换会重启服务，正在跑的造课任务随之中断。发布前先确认 `apps/classroom/data/classroom-jobs/` 下没有 `running` 状态的任务。

两处踩过的坑，脚本已处理，但用其他方式部署时要注意：

- Turbopack 产物 `.next/node_modules/` 里是外部包（pg、sharp、shiki 等）的符号链接，指向构建机绝对路径，直接上传会悬空，对应路由 SSR 直接 500。`pnpm build` 末尾会跑 `scripts/relink-turbopack-externals.mjs` 改写成相对路径；用 `npx next build` 单独构建时要手动补这一步。打包保留符号链接本身，不要解引用拷贝，sharp 带平台原生二进制。
- 只有 `/classroom/[id]` 路由加载 shiki，`/health` 与 `/api/classroom` 都不加载。所以健康检查必须包含一条真实课程页，否则符号链接断了也看不出来（8 月 15 日曾因此漏网一天）。

## 四、验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8001/health          # 引擎 200
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3210/api/classroom   # 课程墙清单 200
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3210/classroom/<id>  # 课程页 200，<id> 取清单里任意一门
```

第三条不能省。浏览器会用客户端渲染把 SSR 500 兜回来，页面看着正常，必须看状态码，或确认返回体里没有 `id="__next_error__"`。
