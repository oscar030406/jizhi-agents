# 教具评测量表

白板那条线量的是「一张板书排得好不好看」，五个维度全是版面（可读性 / 重叠 / 渲染正确 /
内容完整 / 版面逻辑）。教具不一样：它的失败几乎从不长在版面上——模板池的排版是站内
React 算的，坐标 LLM 碰不到，所以教具几乎不会「重叠」「越界」。教具的失败长在
**参数**上：控件在但拖了没反应、模板选对了但填的是别的题材、点开详情位是空的。
所以这里另起一套五维，只有最后一维和白板那套重合。

## 一、五个维度（1–10 分）

### W1 交互有后果 `interaction_consequence`（权重 0.30）

学生动了控件之后，画面里变的那部分是否携带教学信息。判的不是「有没有控件」，
是「动完之后不一样，而且这个不一样讲得出道理」。

**为什么是它、为什么最重：** 这是教具与一张静态图的唯一分界线。模板池把排版风险
压掉之后，剩下的头号死法就是参数退化——矩阵每行相同、评分全打 3 分、滑块绑在
不参与运算的系数上。这些配置全部合法、截图全部好看，只有真去动一下才现原形。

- 9–10：主控件每动一次，画面都给出教学上讲得通的新信息，且变化幅度肉眼可见。
- 5–6：变是变了，但变化要么极其微弱（曲线肉眼看不出形变），要么与本课无关。
- 1–2：动了等于没动。

### W2 教学意图达成 `teaching_intent`（权重 0.25）

拿用例里的 `intent` 那句话当参照物：只看这个教具，学生能不能得出那句话说的结论。

**为什么是它：** 模板选对、参数合法、画面漂亮，但讲的不是这门课要讲的东西——这是
生成端最常见的低质形态（讲量化拿一条线性曲线，讲多智能体编排拿一条没有分叉的直链）。
没有 `intent` 做参照，模型看图只会夸「结构清晰」。这一维是整套量表里唯一需要外部
参照物的，所以每份用例必须写 `intent`，缺了就不该进用例集。

- 9–10：不用旁白，光靠这屏就能得出 intent 里的结论。
- 5–6：沾边，但要老师补一段话才连得上。
- 1–2：教的是另一件事。

### W3 状态反馈可读 `state_feedback`（权重 0.15）

学生知不知道「现在是第几步 / 当前系数是多少 / 刚才那一下改了什么 / 该看哪个数」。

**为什么它单独成一维、不并进 W1：** 变化发生了和学生看懂了变化是两回事。组件那半边
（步号、τ 值、斜率、得分）是写死的，跑不掉；真正会缺的是**配置提供的那半边**：
`carries`（这一步交出去什么）、`captions`（这次合并为什么合它）、`observations`
（拖到哪里该看到什么）、`note`（这个节点是干嘛的）、`guide`（先动哪个）。
这些字段在 schema 里全是可选的，省掉照样过校验，所以必须有人盯。

- 9–10：每个状态都有名字和解释，学生知道下一步该拖哪。
- 5–6：数字在但没人解释它意味着什么。
- 1–2：只有画面在变，没有一句话说变的是什么。

### W4 信息密度 `information_density`（权重 0.15）

一屏承载的教学内容是不是刚好：既不是凑够下限的三步流程，也不是十二个节点糊成一团。

**为什么是它：** 模板的参数自由度已经被刻意压过（步数 3–8、维度 2–5、节点 ≤12），
但**填满下限就合法**——3 步、2 维、2 选项的骨架配置永远过校验。密度太低的教具比
没有教具更糟，它占了一屏还什么都没讲。反过来，制造域那种一口气塞 12 个节点的拓扑图
也在这一维扣分。

- 9–10：内容量撑得起一屏，又没有一处要眯眼看。
- 5–6：明显偏空或偏挤，还能用。
- 1–2：骨架配置（凑够下限）或糊成一团。

### W5 版式可读 `legibility`（权重 0.15）

文字不截断不溢出、数字和坐标轴渲染正确、条形和曲线落在画面内、中文不出豆腐块。

**为什么保留这一维、又为什么权重最低：** 这是唯一必须看像素才能回答的一维——
config 判不出「这个 label 撑爆了框」「曲线跑出了视窗」。但模板池的排版是确定性的，
这一维在正常配置上基本满分，只有超长字段（`label` 卡了 8 字，`cells[].text` 的
14 字上限只写在文档里没进 schema）才会掉分。它是白板那套量表唯一能平移过来的经验。

- 9–10：任何一处文字和图形都完整可读。
- 5–6：有截断或挤压，但主要内容还读得出来。
- 1–2：关键内容被裁掉或叠在一起。

**加权总分只在无红线时才有意义。** 命中任意一条红线 = 直接否决，不算加权分——
一个「点了没反应」的教具，版式再干净也不该被平均分捞上岸。

## 二、红线（B 码，一条即否决）

> 这套 B 码是教具量表自己的，B1–B4 与 PBL planner 那套 B1–B17 不同名不同义，别串。

| 码 | 名字 | 什么算犯 |
|----|------|----------|
| B1 | 单键死局 | 整个教具的可操作面只剩一个推进/完成按钮，按下前后教学内容不变。典型形态就是自由 HTML 教具里那个「我已学完」——全屏说明文字加一个 Done。模板教具的等价形态是步进类的每一步内容逐字相同。 |
| B2 | 控件空转 | 控件在，但数学上不可能改变输出：死滑块（绑定的系数不进这个曲线族的公式）、注意力矩阵各行相同、候选词 logit 全等、取舍矩阵每个维度下所有方案同分。 |
| B3 | 点了没内容 | 主交互是「点开看详情」，而详情位整个是空的：拓扑图全部节点无 `note`、流程步进器全部步骤无 `carries`。学生点下去只有高亮，没有一句话出现。 |
| B4 | 默认态空屏 | 一次都不点时首屏没有教学内容。已实证的形态是曲线在默认系数下溢出被组件的保护全部丢弃，只剩一副空坐标轴；步进类第一步是纯占位（「初始状态」加一句空话）也算。 |

B1 是这条评测线的立项理由（`docs/04-research/openmaic-upstream-audit-20260823.md` 第 13 条）；
B4 对应最早实证的教具病灶「不点下一步就是一片黑」。

### 谁来判：机械 / VLM 分工

红线是一票否决，判错的代价比维度分判偏大得多。所以凡是能从 config 或 HTML 源码算出
确定答案的，一律机械判，不许模型看图猜。

| 码 | 机械判（`redlines.ts`，无需模型） | 交给 VLM（需要多帧截图） |
|----|-----------------------------------|--------------------------|
| B1 | 步进类各步内容去重后只剩一种；自由 HTML 源码里可操作元素 ≤1 | 交互元素虽多但全是装饰（比如五个按钮都弹同一段文字） |
| B2 | 死滑块（系数不在曲线族公式里）、注意力矩阵行全同或行内全同、logit 全等、取舍矩阵各维度同分 | RAG 沙盘换 query 排名不变（打分函数在组件里没导出，抄一份会漂移，交多帧看） |
| B3 | 拓扑图全节点无 `note`、步进器全步无 `carries` | 详情位有字但全是废话（「这是一个重要的节点」） |
| B4 | 曲线在默认系数下可画点数 < 2 | 首屏虽有内容但全是占位话术；首屏被浮层挡住 |

机械那一半已经跑通，见 `redlines.ts`。VLM 那一半的提示词在下面第四节，
它只被允许在**机械检查放行之后**再判剩下的形态——已经被机械判死的用例不再送模型，
省钱，也避免两套结论打架。

## 三、截图探针（交互后帧该怎么拍）

W1 和 B1 都要求至少两帧：默认态一张，动过之后一张。动什么由 `templateId` 决定，
与用例内容无关，所以探针写在这里而不是逐份用例里重复。

| templateId | 默认态 | 交互后应拍 |
|------------|--------|-----------|
| `attention_playground` | 直接截 | 点最后一个 token；再把温度滑块拖到最小 |
| `bpe_merge_stepper` | 直接截 | 连点「合并一次」到最后一步 |
| `temperature_sampler` | 直接截 | 温度拖到最小截一张，拖到最大再截一张 |
| `rag_retrieval_playground` | 直接截 | 依次点每个预设问法，各截一张 |
| `parameter_curve` | 直接截 | 每个滑块拖到量程两端各截一张；开了 `showTangent` 再拖切点 |
| `process_stepper` | 直接截 | 点到中间一步，再点到最后一步 |
| `tradeoff_matrix` | 直接截 | 只留第一个维度截一张，只留最后一个维度再截一张 |
| `layered_graph` | 直接截 | 点入度最高的那个节点 |
| 自由 HTML | 直接截 | 依次点每个可操作元素，各截一张 |

## 四、VLM 提示词

以下整段可直接搬进打分器（对应白板那条线 `whiteboard-layout/scorer.ts` 里的
`RUBRIC_PROMPT` 位置）。输入是同一个教具的一组截图：第一张是默认态，其余是按上表
动过之后的状态；外加用例的 `intent` 与 `name`。

```text
你在评一个课堂交互教具的质量。给你的是同一个教具的一组截图：第 1 张是学生什么都没点时的
默认状态，后面几张是按顺序操作过之后的状态。

教具名称：{{name}}
这屏的教学意图（判分参照物，不是给学生看的文案）：{{intent}}
操作序列：{{probes}}

先明确两件事：
- 这是课堂里的一屏教具，不是海报。留白正常，不因为空而扣分。
- 你手上有多帧。判「交互有没有后果」必须对比帧与帧的差异，不许只看第一张就下结论。

按 1–10 给下面五个维度打分（10 = 无可挑剔，1 = 报废）：

1. interaction_consequence — 学生动了控件之后，画面变的那部分是否携带教学信息。
   对比各帧的差异：变化肉眼可见吗？变化讲得出道理吗？还是只有高亮和序号在动？
   如果多帧之间几乎没有差别，这一维不得高于 3 分。

2. teaching_intent — 只看这个教具（不看旁白），学生能不能得出上面 intent 那句话说的结论。
   模板形态与教学意图错配（讲分叉拓扑却画成一条直链、讲权衡却只列参数表）在这一维重罚。
   只是"看起来很专业"不给分。

3. state_feedback — 学生知不知道现在是什么状态、刚才那一下改了什么、下一步该看哪。
   看的是配置提供的那半边：步骤有没有说明这一步交出去什么、每次变化有没有一句话解释、
   有没有告诉学生该拖到哪里去看什么、点开节点有没有内容。数字在但没人解释它意味着什么，
   最多 6 分。

4. information_density — 一屏的内容量是否撑得起一屏：既不是凑够最少步数的骨架，
   也不是塞到糊成一团。内容明显偏空（三步流程每步一句套话、两个方案两个维度）最多 5 分。

5. legibility — 文字有没有截断溢出，数字、坐标轴、公式渲染是否正确，条形和曲线是否落在
   画面内，中文有没有出现方块或缺字。

overall：1–10 的整体判断，按 W1 0.30 / W2 0.25 / W3 0.15 / W4 0.15 / W5 0.15 的权重给，
但你有权因为某一维塌得特别厉害而进一步压低。

vlmRedLines：只列你从画面里看出、而配置层查不出的红线，从 ["B1","B2","B3","B4"] 里选，
没有就给空数组。判据：
- B1 交互元素虽多但全是装饰，点哪个都弹同一段东西
- B2 换 query / 换选项之后排名或结果完全没变
- B3 详情位有字但全是废话，等于没写
- B4 首屏虽有东西但全是占位话术，或者被浮层挡住

issues：1–5 条具体问题，用一句话说清是哪里、什么毛病，像老师指着屏幕说话那样。

只输出一个 JSON 对象，不要 markdown，不要代码围栏：
{"interaction_consequence":{"score":N,"reason":"..."},"teaching_intent":{"score":N,"reason":"..."},
"state_feedback":{"score":N,"reason":"..."},"information_density":{"score":N,"reason":"..."},
"legibility":{"score":N,"reason":"..."},"overall":N,"vlmRedLines":[],"issues":["..."]}
```

## 五、结算

1. 先跑机械红线（`redlines.ts`）。命中 → 判 `reject`，不送 VLM，报告里写清是哪条哪处。
2. 没命中 → 拍默认态 + 探针帧，送 VLM。
3. VLM 回的 `vlmRedLines` 非空 → 同样判 `reject`。
4. 都干净 → 加权总分入表：`0.30·W1 + 0.25·W2 + 0.15·W3 + 0.15·W4 + 0.15·W5`。

报告里红线数和加权均分要分两栏列，不能把 reject 的用例当 0 分拉进均值——
那会让一次红线在均值里被稀释成"低了一点"，正是 B 码体例要避免的事。
